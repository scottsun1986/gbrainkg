# 问答回复排版修复

## 根因与修改

原 ChatScreen 将正文切成粗体和引用两个类型，其余 Markdown 全部按文本输出；`.answer` 使用统一 pre-wrap 和衬线字体，缺少段落、列表、表格及代码布局规则。

- 新 AnswerMarkdown 使用现有 marked 的 GFM lexer 构造 React 语义节点，支持段落、换行、标题、嵌套/任务列表、引用块、表格、链接和代码。旧会话与新流式回答使用同一组件。
- 正文采用屏幕阅读字体、明确行高与块间距；表格/代码在内部横向滚动，答案容器 min-width=0，避免撑破手机页面。列表保留序号及缩进，代码保留原始空白。
- 引用只按当前消息的准确 source index 绑定；普通数字、未知引用、代码内容和链接标签不转为引用按钮，消除旧答案借用其他答案来源的情况。
- 模型 HTML 仅显示为文本，危险 URL 不生成链接，外链图片不自动加载。渲染不修改事实或权限判断。
- 中文/英文生成规范要求正确空行、列表、表头分隔行与代码围栏；简单答案保持简短，禁止整篇套代码围栏。已完成回答 memo，引用点击使用稳定回调，流式刷新不反复解析历史正文。

## 可重复的排版验收

实际组件和全局样式生成的离线预览：`/tmp/gbrain-answer-layout.html`。它是模拟回答，不是供应商质量或线上状态证据。

```bash
cd apps/web
npx tsx __tests__/answer-layout.fixture.tsx /tmp/gbrain-answer-layout.html
cd ../..
python3 tests/e2e/chat_answer_layout.py
```

脚本验证 1440px 桌面、390px 手机及深色、320px 小屏：段落间距、列表序号、表格键盘滚动、代码空白、引用位置和全页面无横向溢出，并输出截图至 `/tmp/gbrain-answer-layout-screenshots`。该脚本不访问 API 或模型，不创建业务数据。
