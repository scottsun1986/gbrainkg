# 章节列举与多源冲突修复（2026-10-02）

本批修复已构建并更新测试环境。生产仍为 2026-10-01 发布的版本，本批没有再次发布生产。

## 根因

1. 章节补检使用删词后的整句匹配标题，`请列出《…》的全部章名` 留下请求词和书名号，未命中目标文档后退到全库章节扫描；随后 Top-K 选择混入其他文档并截断章节。办公室解析结果中的 `\##` 转义标题也未被原来的章节正则识别。
2. 默认全库包含多份重复的测试制度。按文档 ID 限额不能去除跨文档重复正文，重复片段占据候选与上下文，真实手册和 V2 未同时进入答案。多处仅以正文前 30 个字符去重，也可能错误合并前言相同、后文规定不同的片段。
3. 主回答请求和流读取没有独立超时，并依赖连接关闭来结束流。上游未及时结束时，测试出现约 187 秒等待后无正文；没有证据表明该等待与此前授权变更问题相同。
4. 版本家族存在将“手册”等业务文档类型改写为“制度”的推断，并跨知识库按标题合并。上传日期还被当作缺失生效日期的替代，可能错误暗示新版取代旧版。

## 实现

- 明确书名的章节枚举改为完整文档操作：精确匹配可访问的已发布文档，读取全部分块、核对数量并经过既有 ACL、时效和不可变原文绑定。按原文顺序直接提取编号章节，兼容转义 Markdown，不依赖大模型补造清单。
- 只展示完成原文绑定的完整文档；缺块、原文不可验证或超出 5,000 块扫描上限时明确说明无法确认全部章名。同名文档按知识库分别呈现，按文档合并引用并保留每个原文块的证据引用。
- 在原生候选配额之前先做权限和原文校验，再按完整正文指纹处理重复片段；多检索臂在重排前再次去重。各合并路径用完整正文指纹替代前 30 字，保留不同决定性数值。仍使用原有向量、全文、图谱与重排协同，未加入考勤业务词表或规则。
- 去掉业务文档类型的标题别名；标题家族限定于选定知识库，生效日期缺失保持未知。提示词要求并列比较与问题相关的不同规定，说明各自适用范围，不凭文件名、上传时间或标题相似度断言替代关系。
- 更新答案缓存策略版本，避免复用旧策略生成的答案。
- 主生成流增加 45 秒无响应超时、120 秒总生成时限，保留用户取消与授权取消；收到 `[DONE]` 后退出，释放读取器与定时器。超时反馈明确错误，避免一直等待。
- 清理证据门禁过滤后残留的孤立角标、每行不成对的加粗符号和末尾空标题，保留代码字面量，不放行被拦截的事实。

## 真实回归

没有改为只测限定语料、没有降低原先多源成功条件。章节用例从只检查第一/第八章加强为核对八章完整名称和保存后重读；冲突用例保留两份真实制度、08:30 与 09:00 和保存后重读要求。

| 用例 | 范围 | 结果 | 单次总延迟 |
|---|---|---|---|
| P2-05 全景列举：考勤手册全部章名 | all | PASS | 14.67 秒 |
| P3-02 多源冲突并列：两份考勤制度时间均呈现 | all | PASS | 49.55 秒 |
| P3-02 多源冲突并列：两份考勤制度时间均呈现 | 南京分公司知识库 | PASS | 24.40 秒 |
| P3-01 口语→术语：员工夏天几点上班 → 夏令时 08:30 | all | PASS | 40.41 秒 |

最终排版清理后再次执行默认全库 P3-02，结果 PASS，50.37 秒，保存后重读仍含两种时间。见[最终排版版本的真实问答](outline-conflict-final-format-live.json)。

默认全库章节清单分别列出总部与南京同名文档的八章，引用合并为两个文档来源。默认全库冲突答案包含真实详细手册与 V2，同时展示 08:30 和 09:00，并保留其他可见测试制度的不同规定；系统没有删除测试语料或硬编码排除其名称。

数据见 [最终真实问答及回归结果](outline-conflict-live-regression.json)、[首轮回归](outline-conflict-live-first-pass.json)、[修复前默认全库问答](outline-conflict-before.json)。最后一次排版清理同时对这些真实输出进行[重放核验](outline-conflict-format-replay.json)，确认所有目标时间与章节事实仍被保留。
