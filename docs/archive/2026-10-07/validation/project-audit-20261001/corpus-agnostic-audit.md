# 通用性与关键词硬编码检查（2026-10-02）

检查 API 检索、关系解析、查询分解、证据核验、计数、知识图谱及 Parser 的执行规则。业务词出现在测试数据、代码注释或用户资料中不等于检索硬编码；检查重点是可执行字符串、正则、默认词表与加权分支。

## 已修复

| 位置 | 遗留问题 | 通用处理 |
| --- | --- | --- |
| retrieval-arms.ts | 仅 `EMP` 开头的紧凑编号得到专门召回优先级 | 任意字母/下划线前缀加数字的编号使用同一结构规则 |
| retrieval-arms.ts | 无论实际目录是什么，都注入第一至第五章、总则/罚则等查询词 | 删除虚构章节，保留问题原有结构词、目录意图和完整原文章节枚举 |
| retrieval-arms.ts、agentic-rag.service.ts | 开关可启用人物/影视等评测题型的专用分解 | 删除这些分支，统一使用模型计划与通用句法；旧开关不再改变处理逻辑 |
| corpus-agnostic-config.ts、relation-extractor.ts | 内置关系及同义词表，关系识别只覆盖预设词汇 | 默认词表为空；问题语法提取实际属性，语义由模型解析；仅接受显式配置的别名，并校验配置格式 |
| chat.service.ts | 亲属、影视、创作、院校、所有权、地理等关系各自使用专用实体抽取正则 | 关系标签取自问题/显式配置，实体候选按通用句法与原文结构抽取；修复通用匹配吞掉实体首词的问题 |

| table-count.ts | 只从第一个逗号前取标题线索 | 在完整问题中匹配实际文件标题片段，支持条件前置、标题后置；条件与阈值仍来自问题和完整原文 |
| corpus-agnostic-policy.spec.ts | 扫描实际上只覆盖 chat 目录，且把注释也当作执行规则 | AST 扫描整个 API 的字符串、模板及正则，新增业务样例、编号特例与评测开关回归防线 |

近期计数修复没有在执行代码中写入“息壤杯”、软件研发中心、软研中心混成旅、团队名或90分阈值。保留的分词停用词、计数/对比意图、数值运算符、文件/章节结构与资源预算都是通用语法或算法参数，不包含部署方业务映射。KB 的 domainTerms 和显式关系配置仍可由使用方维护，产品默认不注入业务词。

验证中另外发现首次并发查询会在 BrainScopeMember 的空更新 upsert 上发生唯一键冲突，使问答流没有正文。已改为原子 createMany(skipDuplicates)，保留已有成员记录及时间戳，未改变权限口径。
