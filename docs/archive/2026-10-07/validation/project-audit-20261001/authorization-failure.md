# 测试环境问答授权变化故障

## 原因与证据

2026-10-01，本机测试 API（127.0.0.1:3202）由手动后台进程占用端口，同时
`llmwiki-api.service` 保持自动重启。systemd 的进程会先执行 Nest 初始化、再绑定
端口；每次启动都对六个默认角色执行相同值的 upsert，并对无匹配行的知识库执行
owner 回填。数据库的语句级授权触发器仍会增加版本，造成问答快照失效。

两次复现均在 Source 新鲜度校验阶段失败，授权版本分别从 25108 增至 25121、
25303 增至 25316，未发现授权有效期到期。关闭重复启动服务后，同一问答完整运行
28.434 秒，授权版本始终为 26291。这确认故障源为后台重复初始化引起的版本变化。

## 修复

- 停止重复启动，关闭手动 API，并恢复由本机 systemd 单一管理测试 API。
- API 初始化前检查监听端口，端口已占用则立即退出并给出明确诊断信息。
  这是启动前检查，不能作为两个进程同时启动时的互斥锁；实际端口绑定仍由操作系统裁决。
- 默认角色定义未变化时不执行 upsert；旧员工角色权限已收敛时不重复更新。
- 无需要补归属的行业知识库时不发出空 updateMany。
- 保留授权快照校验、撤权中止、严格输出屏障和数据库授权触发器。

## 验证

- 新增启动端口占用/释放和非法端口测试，以及初始化幂等性和缺失角色修复测试；
  连同 PermissionService 原有测试，18 项通过。
- `pnpm test`：6 个任务成功；API 116 个套件、893 项通过，原有词法集成 5 项跳过；
  Web 50 项通过。
- `python3 tests/integration/run-core-checks.py --database gbrain_core_opt_test`：
  独立测试数据库中的版本发布/回滚、图谱投影、入库替换和真实非 BYPASSRLS 权限矩阵通过。
  严格输出/撤权提交串行化通过，撤权后的旧授权版本不能输出缓存内容。
- 已占用 3202 时再次启动编译后的 API：退出码 1，提示端口已占用，未执行权限初始化。
- systemd 接管后：API ready，authorization=true，MainPID 与端口监听 PID 一致，NRestarts=0；
  初始化前后授权版本均为 26291。
- 接管后的真实 SSE 问答完成检索、生成和保存，耗时 28.743 秒，授权版本全程稳定，
  未出现 Authorization changed 错误。
- 第二个文档内容问题在 80.397 秒完成答案生成、引用验证和消息保存；授权版本始终为
  26291，同样未报错。该耗时仍不理想，检索和生成性能需要继续优化，不能把故障修复
  等同于体验优化已完成。

本次没有操作生产环境。上述时延仅为测试机的单次观测，不能据此宣称检索质量或性能达到 SOTA。
