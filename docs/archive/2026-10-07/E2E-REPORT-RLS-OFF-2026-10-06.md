## 2. 本轮发现并修复:P0 问答展示被"来源已失效"整体阻断

- **现象**:引用中含**派生页**(RAPTOR 宏观摘要/图谱摘要等 compiled-truth 页面,无源文档 id)的回答,读侧被 `validateEvidenceDependencies` 判 false,UI 显示「该回答的来源已失效或您已无权访问」,而答案本体已正确生成落库(Zeta-R3-2127[1][2])。
- **根因**:`captureEvidenceDependencies` 的守卫 `citations.some(c => !c.docId && !c.documentId) → return null`——任一派生引用即整体 null → manifest 为空 → 读侧全量阻断。首轮 E2E 未命中派生引用故未暴露;与 RLS 移除无关,属严格输出特性的边界缺陷。
- **修复**(apps/api/src/permission/evidence-dependencies.ts):捕获时仅对**文档型引用**建清单,派生页引用不参与(其可读性由 compiled-truth 授权链路另行校验);清单为空才返回 null。文档引用的版本/哈希/时效校验语义**不变**。
- **验证**:相关 33 单测绿;界面复测问答命中事实+引用角标+来源正常;被阻断的历史消息属既有脏数据,不回溯。
- ⚠️ 该修复位于**用户未提交的 RLS 移除工作区**中,请随该批改动一并提交。

## 5. 结论

1. RLS 移除后的**权限边界由应用层完整承担**:本轮 49 用例 + 5 项越权探测全部通过,隔离、授权、管理范围、只读强制与 RLS 时代行为一致。
2. 发现并修复 1 个 P0(派生引用阻断问答展示),该缺陷与 RLS 移除无关但属主链路,已修复复测通过;修复文件在用户工作区,需随 RLS 移除改动一并提交。
3. 提示:DB 不再有兜底防线——后续新增查询必须走 PermissionService 体系;建议为"绕过应用层鉴权直查 DB"的场景(如运维直连)另行约束。演示/生产环境需同样应用这两个迁移并发布本修复后方可对齐。

## 6. 追加修复(2026-10-06 22:30,用户反馈)
