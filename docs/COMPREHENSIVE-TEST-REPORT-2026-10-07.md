## 3. 测试中发现的问题与处置

| # | 级别 | 问题 | 根因 | 处置 |
|---|---|---|---|---|
| 1 | P1 | 服务重启后 BullMQ 任务丢失，文档滞留 `indexing` 且 `/retry` 拒绝非 failed 状态，无自愈（arguana 100 篇卡 19 分钟，手动 DB 置 failed 后经 API retry 恢复） | 看门狗 `recoverStaleIngestions`（5 分钟阈+10 分钟周期）本次未生效，根因待专项复现 | ✅ 已恢复数据；📋 已记录 SOTA-ASSESSMENT §4.3（建议启动扫描超时 indexing 自动置失败） |
| 2 | P2 | 登录接口限流 10/min：多测试编排并行登录触发 429（早前一轮套件中段 429 连锁失败的根因之一） | `AUTH_LOGIN_THROTTLE_LIMIT=10` | ✅ 编排统一为单次登录复用 token；建议测试环境白名单 |
| 3 | P2 | BEIR 个别空正文文档导致灌库 400 且管线中止（scidocs） | API 拒绝空 content；管线无兜底 | ✅ `beir_pipeline.py` 空文本以标题兜底（标题含 BEIR 标记可检索回溯） |
| 4 | P2 | 检索接口偶发 5xx（灌库高负载窗口），管线曾直接判失败 | 无重试 | ✅ `beir_pipeline.py` 检索加 5xx/429 退避重试（4 次指数退避） |
| 5 | P3 | 语料生成器缺陷：考核表仅生成 EQ-0001~0040，致 P2-01 首轮失败（模型正确回答"未覆盖 EQ-0077"实为正确行为） | 测试语料 bug，非产品缺陷 | ✅ 语料修正为 80 行后 P2-01 通过 |
| 6 | P3 | 锚点引导脚本 xlsx 上传路径 401（自拼 multipart 兼容性），xlsx 经 curl 灌入成功 | 脚本工具问题 | 📋 遗留（语料已完整，脚本标记 best-effort） |
| 7 | P3 | 权限可见性缓存（TTL 5s）导致"新建 KB 立即读取"404 | 设计内缓存窗口 | ✅ 编排器加可见性等待轮询 |

**全程无未处置的 P0/P1 产品功能缺陷；单元、E2E、GUI 三层全绿。**

## 5. 遗留与建议（优先级序）

1. indexing 滞留自愈修复（P1，见问题 #1）。
2. 多跳端到端答案质量（历史 F1 0.10-0.20 vs 公开 SOTA 0.4-0.6）：答案抽取/生成层是下一个 SOTA 攻坚点。
3. `chat.service.ts` 307KB 拆分（持续重构）。
4. 检索通用性：剥离中文制度语料特化 boost 常量至可配置 profile（本次 nfcorpus 等跨域分数可作回归参照）。
5. 测试环境登录限流白名单 + xlsx 上传脚本修复。
