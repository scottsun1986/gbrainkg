# v53.0 — 语料无关（Corpus-Agnostic）与去业务硬编码大版本

本版本落实项目检索架构铁律「**拒绝业务硬编码**」：检索与语义对齐逻辑必须保持通用
（Corpus-Agnostic），严禁针对特定业务场景在代码中硬编码专用同义词表或正则加权分支。
对**问答链路提示词、纯文本标题判定、权限初始化**做了全量审计与去硬编码，并在保持
功能等价的前提下完成测试环境验收。

## 主要变更

### 1. 标题判定去业务词（`d434810`）
- `apps/api/src/chat/ordered-answer.ts` 的纯文本标题判定，原先用**考勤/薪酬业务词**作为区分特征：
  - `HEADING_RULE_LIMIT` 含 `扣发|扣除|扣款|罚款`；
  - `HEADING_PREDICATE` 含 `打卡|考勤`。
- 这些是语料特定的业务词，违反语料无关原则。已移除；标题 vs 规则的判定改由**结构信号**承担
  （限量措辞、情态/谓词、数量），语义等价，不依赖任何业务词表。
- 单测改用**结构样例**替代业务样例。

### 2. 权限初始化去角色名（`2418d71`）
- 启动时的角色初始化原先**按具体角色名硬编码**（`研发中心员工`）收敛过量管理权限。
- 改为**通用规则**：任何**非内置角色**只要携带**通配权限 `*`** 或**未知权限**
  （旧版本遗留、或越权提升），即收敛为基础用户权限。
- 判据是**权限集合本身**，不是角色名；对遗留/越权数据通用，也不会误伤管理员通过接口
  合法配置的自定义角色（接口本就禁止给非受保护角色授予 `*`）。

### 3. 提示词与检索全量审计
- 问答链路全部 LLM 提示词（答案、查询改写/探针、表格、重试等）经审计均为**通用规则**，
  不含业务同义词表或业务正则加权分支。
- 保留的默认词表均为**通用结构/属性词汇**且可用环境变量覆盖，例如 GraphRAG 组织/系统/制度
  后缀 `GRAPHRAG_*_SUFFIXES`、文档体名词，属文档结构与通用属性，非业务场景词。
