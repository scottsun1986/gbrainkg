# 知识问答召回流程全链路分析与切片/入库优化（2026-10-07）

> 现象：cy 提问"研发人员的绩效组成包含哪几个部分。"时，偶发漏掉"能力指标"（有时三指标齐全，有时只有业绩+行为）。
> 目标：完整梳理召回流程，定位"小切片被忽略"的机制，复查被排除的切片是否应排除，并给出入库（切片/摘要）优化建议。

---

## 1. 现象复现与证据

同一问题连续多轮，回答在"三指标齐全"与"漏能力指标"之间波动。

| 运行 | 引擎/DB 候选 | 重排 | 入选 | 结果 |
|------|--------------|------|------|------|
| run1 | **32** | 正常 | 11（含 3 指标） | 完整 |
| run2 | **1** | **重排服务不可用** | 1（仅 RAPTOR 摘要） | 漏能力指标 |

run2 处理链路关键节点：

```
gbrain_retrieval        : GBrain 返回 1 个候选页面
confidence_rerank       : 首轮候选置信度仍不足，将执行广覆盖扩检
retrieval_escalation    : 扩检后保留 1 个授权候选
rerank                  : 重排服务不可用，沿用 GBrain 候选顺序   ← 关键
evidence_selection      : 已选择 1/1 条证据
answer_context          : 已组装 1 条可引用证据
```

唯一证据是 RAPTOR 章节摘要（extractive fallback）。其"要点章节"列表为：

```
…（一）业绩指标（权重50%-60%）：…；（三）行为指标（权重10%-20%）：…
```

**从（一）直接跳到（三），（二）能力指标整条丢失。**

## 3. 根因（三层）

### R1 入库切片：clause-based 过度切分，小切片无兄弟保护
- 三个指标是**独立切片**：ord 10（业绩，90 tokens）、ord 11（**能力，64 tokens**）、ord 12（行为，270 tokens）。
- 每个切片的 `parentChunkId = section:<charStart>` **各不相同**（`section:1188` / `section:1322` / `section:1422`），因此它们在证据选择里是**三个互不相关的组**，不是"同一条下的原子列表"。
- 后果：能力指标作为最小切片，可被独立丢弃；只有当三者都进入候选池、且被预缝合（相邻 ord）时才作为整体保留。

### R2 入库摘要：extractive fallback 有损
`raptor.service.ts: extractiveSummary` 原实现：
- 标题正则 `^第[一二三四五六七八九十…]+[章节]` **要求行首即"第"**，而解析器输出的条款是 `\*\*第X条\** …`（以 `\*\*` 开头）→ **所有"第X条"标题被漏掉**；
- 仅取**前 12 个**标题（`.slice(0, 12)`）；
- 输出截断到 **900 字**，并把原文尾部直接拼入。
- 结果：摘要"要点章节"只覆盖部分子条款，且**丢失（二）能力指标**。当该摘要成为唯一证据时，回答必然漏项。

### R3 召回鲁棒性：provider 瞬时故障 + 摘要无源切片回补
- 向量嵌入 / 交叉编码重排 provider 瞬时不可用 → 候选塌缩到 1 条、重排不可用；
- 该唯一候选是**派生摘要**（`raptor:true, isSummary:true`），且 RAPTOR 命中**不携带 `sourceChunkIds`**，管线无法把摘要回补为它的源切片；
- 于是**有损摘要成了唯一且不可纠正的证据**。

## 4. 被排除切片复查

- **健康运行（run1）**：召回 11 → 重排 11 → 入选 11，`eliminated: []`、`budgetSkippedGroups` 无。**选择器没有误排任何切片。**
- **故障运行（run2）**：候选池只有 1 条（摘要），原始切片**根本没有被召回**，`eliminated` 为空。
- 结论：本次漏项**不是"选择器把内容少的切片排除了"，而是 provider 故障下"召回塌缩 + 有损摘要"**。正常路径下小切片并未被地板/MMR/预算误杀。

> 仍需注意：由于 R1，小切片在**部分召回**时（三兄弟只召回两个）会因预缝合无法闭合而漏中间项；这是潜在风险，需由 R1 修复根治。

## 5. 入库（切片/摘要）优化建议

### 5.1 切片：保证列举项原子性
- 同一条/同一父小节下的兄弟小项，应共享一个 **sectionGroup**（如 `section:<父条起始>`），使 业绩/能力/行为 作为**原子组**参与选择；
- 或对**低于阈值（如 < 120 tokens）的相邻同父切片做合并**，减少碎片；
- 保留 `parentChunkId` 指向**父条（第九条）**而非当前子项起点，便于"命中任一子项→补齐整组"。

### 5.2 摘要：完整性与可追溯
- 修复 `extractiveSummary`（**已落地**）：识别 `**第X条**`/加粗/列表前缀标题；标题上限 12→可配（默认 40）；输出上限 900→可配（默认 1800）；
- 摘要节点应携带 **`sourceChunkIds`** 并在命中时回补源切片（见 5.3）；
- 优先使用 LLM 摘要；fallback 仅作兜底且需保证"可追溯到源切片"。

### 5.3 召回鲁棒性
- 命中派生摘要时，**回补其源切片**（RAPTOR 节点已有 `sourceChunkIds`），避免摘要单独作答；
- 枚举/完整性类问题（"由哪几部分/有哪些"）**优先原始切片**，派生摘要只作导航；
- provider 故障时，强化**词法/原文兜底**，避免候选塌缩到 1 条。
