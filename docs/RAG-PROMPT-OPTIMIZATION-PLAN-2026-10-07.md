# 知识问答大模型提示词全面审查与最优方案（2026-10-07）

> 范围：`apps/api/src` 中所有参与"知识问答"链路的大模型提示词（不含纯索引期提示词）。
> 目标：盘点现状、枚举全部提问场景、给出可落地的最优提示词方案。
> 原则沿用项目约定：**不裁决、不替用户取舍；多源歧义全部并列；不杜撰；Corpus-Agnostic（无业务硬编码）**。

## 3. 现有提示词的问题清单

### 3.1 架构层（高）
1. **中英文答案提示词不等价**：英文 8 条规则、中文 12 条规则。英文缺失：证据收敛与指标完整性（S30）、章节目录全景列举（S14）、表格行与正文冲突并存（S27）、多源合并的显式规则、客观真实分层回答的细化。→ 英文提问得到更少的保护。
   - **方向（用户确认）**：**以中文为主、英文为辅**。不再维护与中文平行的英文全量规则体；中文规则为唯一权威版本，英文仅作**附加块**（语言强制 + 关键契约摘要），英文自动继承中文的全部场景规则，从根上消除中英漂移。
2. **规则冗长、优先级不显式**：核心提示词约 80 行、规则交叉；"简短"与"范围完整"、"单一理解即结束"与"多源并列"曾多次互相冲突（见 `RAG-PROMPT-RESEARCH`）。缺少一个**显式决策顺序**。
3. **拒答口径不统一**：P11 中英拒答句不同；`retryWithFocusedEvidence` 又用"资料未包含该信息"；`CHAT_REFUSAL_DISCIPLINE` 额外注入一段与 P11 规则7 重复的纪律。同一系统存在 3 套拒答措辞。
4. **动态指令与主提示词重复**：`【表格聚合完整性】`、`【全景统计规范】`、`【编译资料使用规则】` 各自重复了主提示词的若干规则，增加指令稀释。

### 3.2 查询理解层（中）
5. **复杂问题判定依赖关键词**：`classifyQuery` 对"冲突/矛盾"类依赖字面词；用户问"上下班时间要求是什么"不含冲突词 → 被判 simple，不会主动找第二份制度。
6. **子问题/扩展可能漂移**：P2/P3 的 subQueries 为自由文本，缺乏"必须来自问题或证据、不得引入外部实体"的硬约束。
7. **桥接探针噪声**：`extractBridgeEntitiesFromEvidence` 的书名号分支已加关系同句约束（本次），但 `bridge_seed` 的英文大写名抽取仍可能从无关来源取词（如 Git Flow/Code Review）。
8. **P8 只看前 3000 字**：长上下文时可能漏掉答案原句而误判不足，触发无谓补检。

### 3.3 证据裁决层（中）
9. **P8 充分性判据偏"话题"**：虽有"必须有原句 quote"的降级，但缺"同一属性、同一主体、适用范围一致"的显式判据，容易把"相关实体出现"当充分。
10. **P9/P10 提示词过简**：缺少"同一属性/主体/范围"与"多源差异不算矛盾、应全部保留"的判据；P10 用于缓存准入，误判会丢弃合法答案。

### 3.4 答案层（中）
11. **多源差异只覆盖"取值不同"**：对"一份完整、一份局部""不同适用范围""互补规定"的呈现格式未统一。
12. **无显式否定/缺失问法规则**：S15"有没有…"缺 yes/no + 依据 + 缺口的标准形态。
13. **无时间相对问法规则**：S29"今年/本月"缺"以资料明确时间或当前日期为准，不得臆断"。
14. **格式规则只给原则**：多源并列时推荐"按来源分段 + 各自范围"的固定形态，减少模型自选导致的不一致。

### 3.5 校验/输出层（低）
15. P14/P15 重试提示词与主提示词口径需对齐（语言、拒答句、角标格式）。

## 4. 最优提示词方案

### 4.1 总体架构：统一分层 L0–L4

```
L0 共享不变量（所有提示词前缀，6 条）
L1 查询理解与规划   → P1/P2/P4/P6/P7   （产出：查询类型 + 子问题 + 覆盖探针）
L2 证据裁决         → P8/P9/P10        （产出：充分性 + 包含/蕴含集合）
L3 答案生成（核心） → P11/P12/P13/P14/P15（产出：最终答案）
L4 输出校验与拒答   → 确定性门禁 + 统一拒答句
```

核心思想：**把"规则清单"改成"有序决策流程"**，让模型先分类问题，再按场景走固定分支；中英文使用**同一套规则、同一套示例结构**，仅切换语言。

### 4.2 L0 共享不变量（6 条，中英同构）

1. **Grounding**：只依据提供的来源；决定性取值逐字照抄；不得用外部知识补全。
2. **No adjudication**：多源对同一属性取值不同时全部并列，不选其一、不判效力、不合并/平均。
3. **Scope fidelity**：保留来源明示的人群、条件、时间、版本；不泛化、不迁移。
4. **Relation fidelity**：组成 ≠ 评价指标 ≠ 管理流程 ≠ 结果用途。
5. **Coverage before absence**：先核对全部来源，再声明缺失；区分"未记载"与"资料未包含"。
6. **Language mirror**：以用户提问语言作答，保留原实体名。

### 4.3 L1 查询理解与规划（优化点）

**统一问题分类**（输出枚举，供后续分支）：
`fact | definition | enumeration | count | comparison | conflict | multi_hop | procedure | conditional | temporal | aggregate | summary | inventory | structure | absence | follow_up | out_of_scope`

**覆盖探针（新增，关键）**：当问题属于 `fact/definition/enumeration/comparison/conflict` 且问的是"某主体的某属性"时，除主查询外追加一个**覆盖探针**：
> `<主体> <属性>` + 该知识库配置中与该主体同类的文档类型词（来自 KB 配置/问题本身，**不硬编码**）。

目的：让"同一属性可能被多份制度规定"的情形召回多份来源，而非只召回排名最高的那份。

**硬约束**：
- 子问题/扩展/探针**只能**由问题文本或已召回证据中的词构成；禁止引入外部实体。
- 冲突/多源类问题：必须分别针对"不同文件/版本的表述"构造探针，禁止使用"第一份/第二份"等无指代词。

### 4.4 L2 证据裁决（优化点）

**P8 充分性**增加判据：
- 先写出"问题所问的**主体 + 属性 + 范围**"，再找直接陈述该属性取值的原句（保留现有 quote 硬门禁）。
- 只有"话题相关/相关实体出现"不得判 sufficient。
- **多源场景**：若同一属性在多份来源出现且取值不同，判 sufficient（证据已够并列），并列出全部来源；不得因"存在差异"判不足。
- 补检词必须由"问题主体 + 属性"派生，不得使用无关证据中的实体。
- 上下文取样由"前 3000 字"改为"按来源均匀取样 + 命中段优先"（工程项）。

**P9 片段包含 / P10 事实蕴含**增加：
- 同一属性、同一主体、范围一致才判 YES/支持；仅主题/词面相关判 NO。
- 多源差异不视为"不蕴含"，只要各自原句支持各自取值即通过。

### 4.5 L3 答案生成（核心最优方案：中文为主、英文为辅）

**语言架构**：只维护**一套中文权威规则体**；英文提问时在其后追加一个**英文附加块**（语言强制 + 关键契约摘要 + 英文拒答句）。英文不再拥有平行的全量规则，从而自动继承中文的全部场景规则，从根上消除中英漂移。

将现有 8+12 条规则重构为**统一决策流程 + 输出契约**。以下为中文主规则：

```
你是企业知识库问答助手。严格依据【参考知识库资料】作答。

【决策流程（按序执行）】
第 1 步 解析问题：确定 主体 / 所问属性 / 适用范围 / 所需粒度 / 语言。
第 2 步 收集证据：找出所有直接陈述"该属性"的来源（不是"主题相关"，而是"同一属性"）。
第 3 步 分流：
  (a) 多份来源对同一属性取值/规定不同 → 逐份并列，每份标注来源角标与其适用范围；
      不选其一、不判定何者为准或替代、不合并/平均；版本号/上传时间/标题相似不构成取舍依据；
      仅原文明确替代关系或生效元数据时可说明适用状态，且仍保留各来源原文，由用户决定。
  (b) 多份来源一致 → 合并角标（每个来源都须支持该具体断言），否则拆分就近引用。
  (c) 仅一份来源 → 直接作答。
  (d) 无来源直接陈述该属性 → 先给出已支持的部分事实与适用范围，再准确说明未覆盖的细节；
      仅当资料与问题主体完全无关时才整句拒答。
第 4 步 组稿：首句直接给出核心结论（含必要范围限定与角标）；决定性取值逐字照抄；不复述问题、不写套话。

【输出契约】
- 完整呈现匹配原文：当来源中存在直接回答所问属性的原文条款/描述时，除首句结论外，必须把与该问题直接匹配的原文关键表述（摘录或忠实转述）连同角标带到回答中，让用户看到依据；多源分别匹配时逐份呈现；不为求简短省略与问题直接相关的原文要点。完整性只针对所问属性，不扩展到未问的其他属性/流程/子指标。
- 每个事实/数值/结论就近标注 [n]；只使用提供的编号；不得生成来源清单/脚注。
- 保留来源明示的人群/条件/时间/版本为语法主语；不得沿用问题中更宽泛的主体。
- 组成、评价指标、管理流程、结果用途不可互相替代。
- 仅问名称/数量/类别时，只给名称、所问数量、必需范围与角标；不主动附加权重、子指标、流程。
- 并列指标完整性：一个数值若在同一原句中附带阈值/单位/百分比/连带条件，须一并列出。
- 否定/缺失问法（"有没有…"）：先明确"有/无 + 依据"，再给已记载内容或缺口。
- 章节/目录问法：完整扫描目标文档后才可声称"全部列出"，片段不足时明确缺失范围。
- 表格行与正文/锚点事实不一致时：两种事实都陈述（"表格第 N 行为 X，正文为 Y"）。
- 时间相对问法（"今年/本月"）：以资料明示时间或系统当前日期为准，不臆断。
- 反事实/诱导：明确指出资料无此记载或前提不成立，不顺从虚构。
- 排版：自然段或简短列表为主；比较优先分段而非表格；长回答才用 ## 小标题；引用不放进代码块。
- 拒答统一为一句："已知知识库资料中未包含相关信息，无法回答该问题。"
```

**英文附加块（仅当问题不含中文时追加；中文规则仍为唯一权威）**：

```
[English response — secondary instructions]
The user asked in English. The Chinese rules above are authoritative; apply them and answer entirely in English, preserving original entity names; do not answer in Chinese.
Binding points: ground every claim in the provided sources and cite it with its [n] marker; copy decisive values verbatim; when several sources state different values for the same requested property, present every one with its own citation and stated scope and never choose, rank, merge or average them; preserve each source's stated scope as the grammatical subject; never substitute a different relation; check all sources before declaring a gap; if no source addresses the subject, reply exactly: "Based on the provided reference materials, the relevant information is not available."

```

**关键变化**：
- 用"第 3 步分流 (a)–(d)"替代分散的"单一理解即结束 / 多源并列 / 分层回答"三处规则，消除冲突。
- 中文规则是唯一权威；英文附加块只做语言强制与契约摘要，**自动继承**中文的指标完整性、章节列举、表格冲突、否定问法等场景规则，实现中英行为一致且维护量减半。
- 统一拒答句与语言一致性，去掉 `CHAT_REFUSAL_DISCIPLINE` 的重复注入（或将其并入 L0）。
- 场景专属规则（章节列举、表格冲突、指标完整性）改为**由问题分类触发**，不再常驻全部提示词，减少稀释。

## 6. 结论

当前提示词在"组成 vs 指标 vs 流程""多源同属性差异"两个真实失败点上已专项加固，主干可用。主要优化空间有三类：

1. **一致性**：中英提示词不等价、拒答口径三套、动态指令与主提示重复。→ 以**中文为主、英文为辅**收敛：中文唯一权威，英文仅作附加块。
2. **结构化**：规则清单过长且优先级不显式，应改为"分类→有序决策流程"。
3. **场景完整性**：否定问法、时间相对、多源并列的呈现格式、覆盖探针（属性类问题主动找多份来源）仍有缺口。

按 §5 优先级实施，可在不引入业务硬编码的前提下，同时提升准确率、抗幻觉与多源透明度。
