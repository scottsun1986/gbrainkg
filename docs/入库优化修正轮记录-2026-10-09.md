# 入库优化修正轮记录（2026-10-09）

针对对 [入库优化实施验收报告](入库优化实施验收报告-2026-10-09.md) 的复核结论，本轮修正复核中发现的问题。基线为上一轮的 `7efe4a1`/`ab2f331`。未部署演示或生产；全部验证在本地隔离环境完成。

## 修正范围

质量门禁（`pnpm test`、API/Web tsc 与 lint、Parser ruff/mypy 与 pytest、adapter 契约、API/Web 构建）在修正前后均为通过，但复核发现若干**门禁覆盖不到的确定性缺陷**。本轮逐项修正并补齐回归。

### 事实保真（Parser）

| 问题 | 修正 |
| --- | --- |
| `.xls` 合并单元格不写 `merged_range`（与 XLSX 契约不一致） | XLS 分支补齐 `merged_anchor` + `merged_range` |
| `.xls` 合并继承 `display` 用裸 `str(value)`，同一事实出现两个检索串 | 改为复用锚点的格式化 display（`_xls_cell`） |
| 每个表格区域上报整表 merge 列表，无合并的区域也声称拥有 | `Region.merged_ranges` 只返回与区域矩形相交的范围 |
| 无缓存公式的 `display` 为公式文本，被计入 `native_text_chars` 并写入 Markdown | `display` 置空，公式文本只保留在 `formula` 字段；新增 `unresolved_formulas` 计数与告警 |
| 单一合并表头产生 N 个同名 `headers`，列名无法唯一解析 | 仅有合并 presentation 且无自身标签的列回退为列字母；Markdown 投影仍用原始标签，视觉一致 |

### 稳定性（Parser）

| 问题 | 修正 |
| --- | --- |
| 硬杀（OOM/SIGKILL）遗留文件永久占用共享临时预算，之后所有上传 503 | `temp_budget.reclaim` / `reclaim_under_pressure`：启动强制回收，周期内在预算压力下回收；回收地板为最旧在办任务创建时间；`/resource-metrics` 暴露占用与预算 |
| `benchmark_structured_excel.py --rows 1` 崩溃于内联表无 artifact | 明确报错并提示需超过内联预算 |
| `vlm_extractor` 渲染帧 `NamedTemporaryFile` 未指定 `dir=`，绕过记账 | 指定 `UPLOAD_ROOT` |
| `python -m src.main` 不能启动（`__main__` 仍硬编码 `main:app`），且端口写死 8100 | `f"{'src.' if __package__ else ''}main:app"`，并转发 `--host/--port` |
| 图片枚举失败以「0 张图片」返回 200 | `extract_docx` / `extract_pdf_page_images` / `extract_embedded_image_parts` 改为抛出，经 `/ocr-embedded-images` 500 暴露为可重试失败 |

### 授权与数据完整性（API）

| 问题 | 修正 |
| --- | --- |
| QA「同题不同答案」保护读客户端自报 `idProvided`，可被绕过 | `validateQa` 服务端计算 `idProvided`，`import`/`review` 使用服务端值 |
| `getDocument` 只校验 KB 可见性即返回全部 chunk、原始 Markdown 与完整 `parserMetadata` | 追加 `filterReadableDocuments` 文档 ACL |
| `filterReadableDocuments` 不给候选文档加生效时间/生命周期门，与 `readableDocumentSql` 不一致 | 新增 `documentCurrentlyEffective` 作为 SQL 谓词的唯一 Prisma 镜像；默认开启时间门，管理面用 `probe: true` 跳过以便修复已过期候选 |
| 资产接口未传 `?version=` 时返回当前构建元数据（重解析中会返回未发布内容） | 固定到 active published version |
| `QaController.kbId` 未校验 UUID，Prisma 错误逃过过滤器变 500 | 补 UUID 校验 |
| QA 清单/预览查询无 `take`，10 MiB 上传即把全库问答载入内存 | 补 `take` 上界 |
| 审核读取候选 JSON 未防护，删除/损坏时 500 泄漏文件路径 | 读取/解析失败返回 404/400 |
| `countSchema` 只给规划器 200 行预览的值域，导致值只出现在后续行时过滤不可表达 | 标注 `value_domain_is_sample`，规划器提示不把样例当完整值域 |

`docs/RLS-BOUNDARIES.md` 同步更新为与实现一致的访问边界描述。

### 真实环境复现与复验

新增测试：`tests/test_temp_budget.py`（8 项）、`test_structured_excel.py`（合并范围/唯一表头/无缓存公式/XLS 合并）、`test_startup.py`（`python -m src.main` 入口）、`test_extractors.py`（图片枚举失败）、`qa-import.spec.ts`（`idProvided` 不可伪造）、`document-acl.service.spec.ts`（时效门与 SQL 谓词等价）、`knowledge-base.controller.spec.ts`（`getDocument` ACL）、`table-count.spec.ts`（值域样例标记）。

隔离集成：`node tests/integration/core-ingestion-structured.cjs`，真实控制器、数据库与**启动新构建的本地 Parser Worker（0.5.0，端口 8110）**贯通上传→解析→不可变发布→完整聚合→QA 别名/CAS 审核→包内资产 ACL→来源失效→删除，全部通过。指标：10001 源行、解析发布 2.148 s、完整聚合 212 ms、API 峰值 RSS 194,744 KiB。

孤儿回收的端到端复现：向测试 uploading root 放入带旧 mtime 的 300 KiB 源文件、native 工作目录与 `image-unit-*` 溢出文件，`PARSER_MAX_TEMP_BYTES=500000`。服务启动后被全部回收，`/resource-metrics` 报告 `owned_bytes: 0`，恢复可用。

与之前测试的差异：`basic .xls` 合并单元格现带 `merged_range`，锚点与继承单元格 display 一致；无缓存公式不再进入 Markdown 与正文字数。
