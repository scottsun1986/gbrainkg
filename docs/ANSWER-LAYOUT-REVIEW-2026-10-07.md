# 知识问答回答排版全链路审查与系统性优化（2026-10-07）

> 现象：cy 提问"研发人员的绩效组成包含哪几个部分。"时，第二处来源标题（"其二，企业研发管理规范：…"）未与"其一…"并列成块，而是黏在前一段末尾。
> 目标：盘点回答排版涉及的全部环节，定位不一致根因，给出系统性优化建议并落地关键修复。

---

## 1. 现象复现（原始字节）

```
…高级工程师/架构师可调整为"业绩50%、能力35%、行为15%" [2]\n**来源《企业研发管理规范》**：研发人员考核采用… [3]
```

关键点：第二处来源标签前只有**单个 `\n`**（甚至完全黏连在句尾）。前端用 `marked` 以 `breaks: true` 解析，**单个换行只是同一段内的硬换行**，不产生新段落，因此第二处来源无法与第一处并列成块。

---

## 2. 排版链路全环节清单

| # | 环节 | 位置 | 现状 | 问题 |
|---|------|------|------|------|
| L1 | 模型生成（排版规则） | `answer-style.ts`（拼入答案提示词） | "段落和块元素之间留一个空行"；比较优先分段 | 未定义"块"的边界；未要求来源/分节标题独立成块；未禁止单换行分隔块 |
| L2 | 逐句证据门禁 | `chat.service.ts` grounding gate + `ordered-answer.ts` | 逐句核验，暂扣/放行/丢弃；标题、表格、来源标签走快速通道 | 暂扣半句时可能留下孤立括号/行首逗号等残句 |
| L3 | 有序作答组装 | `OrderedAnswer`（`ordered-answer.ts`） | 按位置拼接；`blockStart` 只在缺失时补**单个 `\n`** | 只补单换行，不足以形成块 |
| L4 | 流式稳定前缀 | `answer-stream.ts`（默认缓冲，`KNOWLEDGE_INCREMENTAL_STREAM` 才开） | 只推 tidy 稳定行前缀 | 增量模式下前缀可能缺空行，靠 `replace` 兜底 |
| L5 | 文本清理 | `tidyVerifiedAnswer` / `dropEmptySectionHeadings` | 去空标题、去孤立角标行、折叠连续空行 | 不补空行；不识别无编号来源标签；不去孤立括号 |
| L6 | **布局规范化（本次新增）** | `normalizeAnswerLayout`（`ordered-answer.ts`） | 块前补空行、拆分粘连标签、去残句行 | 新增，已落地 |
| L7 | 引用重绑 | `citation_rebinding` | 校正 `[n]` | 与排版正交 |
| L8 | 前端渲染 | `AnswerMarkdown.tsx`（`marked` `breaks:true`）+ `answerTokens` 修复 | 单换行=段内 `<br>`；修复"句末加粗标签"为块 | 修复仅覆盖句号结尾，漏了角标/分号结尾与行首 br 情形 |
| L9 | 文档渲染 | `lib/markdown.ts`（`marked` 无 `breaks`） | 与回答**不同语法** | 同一 Markdown 在文档与回答中渲染规则不一致 |

---

## 3. 根因

1. **块分隔语义缺失**：模型把来源/分节标签当作"另起一行"，用单个 `\n`；而渲染语法（`breaks:true`）里单换行不是块边界。缺少**"块必须空行分隔"**的强约束。
2. **块级识别不全**：既有 `isStructuralHeadingLine`/`isSourceLabelHeading` 只认"来源+编号"、章节序号、`#` 标题等；`**来源《标题》**：`（无编号）、`**《标题》口径**（适用范围 [1]）：`（带括号限定）、`其二，…`（序数词）都不被识别。
3. **前端修复覆盖窄**：`answerTokens` 只把"句号紧邻加粗标签"提升为块；标签前是**角标 `[2]`** 或**分号 `；`** 时不触发，标签仍留在原段。
4. **残句清理缺失**：门禁暂扣半句时，孤立 `）` 等标点行会进入正文。
5. **中英/文档语法不一致**：文档渲染无 `breaks`，回答有 `breaks`，同一文本两种表现。

---

## 4. 系统性优化建议

### 4.1 统一"块语法"（唯一权威）

回答只使用固定块类型，并**强制空行分隔**：

| 块 | 形式 | 边界 |
|----|------|------|
| 段落 | 自然段 | 前后空行 |
| 来源/分节标题 | `**来源N《标题》**：` 或 `## 标题` | 独立成行，前后空行 |
| 列表 | `-` / `1.` | 整块前后空行，项间不空行 |
| 表格 | GFM 表格 | 整块前后空行，行间不空行 |
| 代码 | 围栏 | 整块前后空行，内部原样 |
| 引用 | `>` | 前后空行 |

**落地状态**：已实现于 `normalizeAnswerLayout`（L6），作为生成后的确定性规范化；前端修复（L8）仅作兜底。

### 4.2 提示词（L1）— 已增强

`answer-style.ts` 新增："每个块级元素（来源/分节标题、列表、表格、代码块、引用）必须独立成块——标题单独成行，块与块之间恰好一个空行，禁止用单个换行分隔两个块级内容；多来源回答中每个来源的标题与其内容构成独立、平行的块。"

建议进一步：在提示词中给出**一个标准的多来源版式示例**（两来源、各自标题+内容+角标），并统一来源标签写法（统一用 `来源N《标题》` 或 `## 标题`，避免 `其一/其二`、`一、`、`1.` 混用）。

### 4.3 确定性规范化（L6）— 已落地

`normalizeAnswerLayout(text)` 保证：
- 每个块级元素前恰好一个空行（列表项/表格行之间不插入）；
- 识别**无编号来源标签**、**带括号限定（可含角标）的加粗标签**、**序数词标签（其一/其次…）**；
- **拆分粘连标签**（`…[2]；**二、《…》**` → 独立成行）；
- **删除残句行**（仅括号/标点的孤立行；表格、分隔线、代码围栏除外）；
- 幂等、不触碰代码围栏内文本。

### 4.4 前端渲染（L8）— 已增强

`answerTokens` 的加粗标签提升条件扩展为：标签前是**硬换行**，或文本以**句末标点（含 `；`）或角标 `[n]`** 结尾。作为 API 规范化之外的兜底，保证历史消息与增量流也一致。

### 4.5 逐句门禁（L2）— 建议

- 暂扣/丢弃时以**完整句子或完整括号对**为单位，避免留下孤立 `）`、行首 `，`；
- 残句清理目前放在 `normalizeAnswerLayout` 兜底；上游按句处理可从根上减少残句。

### 4.6 渲染语法对齐（L9）— 建议

- 统一 `lib/markdown.ts` 与 `AnswerMarkdown` 的 `marked` 选项（是否 `breaks`），避免同一 Markdown 在文档/回答中表现不同；
- 若保留回答 `breaks:true`（利于模型单换行的行内排版），则必须以 §4.3 的确定性规范化保证块边界。

### 4.7 回归测试 — 已补

- API：`ordered-answer.spec` 覆盖块前空行、粘连标签拆分、列表/表格不拆分、残句删除、幂等。
- Web：`answer-markdown.test.tsx` 覆盖角标/分号/硬换行后的加粗标签提升为块。

## 5. 剩余项与优先级

| 优先级 | 项 | 说明 |
|--------|----|------|
| P1 | 提示词标准版式示例 + 来源标签写法统一 | 从生成端减少不一致 |
| P1 | 逐句门禁按整句/整括号暂扣 | 消除残句根因 |
| P2 | 文档渲染与回答渲染语法对齐 | 一致性 |
| P2 | 表格/列表/代码块的黄金版式回归 | 防回归 |

---

## 6. 结论

回答排版由 **模型生成 → 逐句门禁 → 有序组装 → 文本清理 → 布局规范化 → 前端渲染** 多环节共同决定。本次定位到根因是**"块必须空行分隔"语义缺失 + 块级标签识别不全 + 前端修复覆盖窄**，并通过 **提示词规则 + 确定性 `normalizeAnswerLayout` + 前端兜底修复** 三处协同修复，`cy` 实时验证：多来源回答的两处来源标题已并列成块、无粘连、无孤立括号。全量单测（API 1402 项）与 Web 构建/lint 通过。
