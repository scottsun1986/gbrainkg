# GBrain 权限范围内完整能力升级方案

版本：V1.0（待实施方案）  
编制日期：2026-08-31  
适用项目：LLMWiki / GBrain 企业知识平台

## 1. 文档目的

本方案用于指导平台从“按权限拆分 source、分别检索、应用层合并结果”的实现，升级为：

> 原始知识保持隔离，权限范围内可以跨 source 检索、综合、推理、形成总结和知识图谱；当知识或权限发生变化时，只增量更新受影响的内容；所有结果继续经过平台最终权限校验。

本方案不改变现有业务规则：个人库不可共享，组织库遵循“下级可读上级、上级不可读下级”，行业库支持按人、组织、角色授权，行业库创建者保留删除和管理员设置权，组织管理员只能管理本级及下级组织。

## 2. 升级结论

推荐采用四层架构：

```text
原始 Source 层
  └─ 每个共享范围、权限组或私密范围独立保存原始知识

权限 Scope 层
  └─ 根据用户当前有效权限，形成可复用的 source 集合

GBrain 派生智能层
  └─ 跨 source 检索、Think、Synthesize、事实、实体、关系、图谱、缺口分析

平台安全层
  └─ 数据库最终 ACL、引用复核、缓存隔离、权限撤销即时生效
```

“全局总结”必须解释为“当前用户权限范围内的全局总结”，不能生成一个所有用户共用、且可能混入私密内容的全局大脑。

GBrain 官方文档将 Brain 与 Source 分离，并支持按 source 进行检索隔离和跨 source 读取；Company Brain 示例也采用多个 source、按用户权限读取的方式。本项目应保留这一边界，再增加动态组织、角色和人员授权，以及平台数据库最终鉴权。  
参考：[Brains and Sources](https://github.com/garrytan/gbrain/blob/master/docs/architecture/brains-and-sources.md)、[Company Brain](https://github.com/garrytan/gbrain/blob/master/docs/tutorials/company-brain.md)。

## 3. 当前实现与目标差距

### 3.1 当前已有能力

- 原始文件、规范 Markdown、Chunk 和数据库元数据已经形成入库链路。
- 共享知识库使用共享 source，私密知识按有效读者集合拆分 source。
- 文档变化和权限变化支持增量编译，数据库执行最终权限校验。
- 检索已具备关键词、向量、混合检索、重排、文档回溯和引用能力。
- Dream 有定时任务、运行记录和队列重试。
- 会话支持历史上下文、问题改写和来源链接。

### 3.2 需要补齐的能力

- 当前跨 source 主要由应用层逐个查询再合并，尚未形成权限范围内的原生综合脑。
- GBrain Think、跨 source Synthesize、事实抽取、实体解析、关系和图谱需要形成正式流水线。
- 派生总结尚未以带来源、版本和权限的文档形式进入 RAG。
- 权限变化和知识变化缺少统一事件总线、影响范围计算和版本化 Scope。
- Dream 的执行效果还需要统一展示新增/修改/删除页面、Chunk、Embedding、事实、边、总结、缺口和失败原因。
- 需要建立离线评测集，量化召回率、引用准确率、答案完整性和越权风险。

## 4. 核心设计

### 4.1 Brain、Source 与 Scope

#### Source：原始知识事实源

Source 只保存可追溯的原始知识页面及其结构化元数据，不承载最终业务权限。建议保持以下类型：

| 类型 | 用途 |
|---|---|
| shared source | 组织库、公开行业库等所有目标用户共同可见的知识 |
| private source | 个人库或小范围私密知识 |
| permission-group source | 相同有效读者集合的私密知识 |
| derived scope source | 某一权限 Scope 的总结、事实、关系和图谱派生结果 |

#### Scope：用户当前可见的知识边界

Scope 不是用户副本，而是权限快照和 source 集合：

```text
Scope = 有效用户集合 + 可读 source 集合 + ACL 版本 + 知识版本 + 模型/Schema 版本
```

建议新增：

| 数据对象 | 主要字段 | 作用 |
|---|---|---|
| `BrainScope` | `fingerprint`、`sourceKeys`、`aclEpoch`、`knowledgeEpoch`、`status` | 标识可复用的权限范围 |
| `BrainScopeMember` | `scopeId`、`userId`、`validFrom`、`validTo` | 将用户绑定到 Scope |
| `BrainDerivedPage` | `scopeId`、`kind`、`derivedFrom`、`inputFingerprint`、`contentHash` | 保存可追溯的总结、事实、概念和缺口 |
| `BrainChangeEvent` | `eventType`、`resourceId`、`version`、`affectedScopes`、`status` | 统一处理知识和权限变化 |
| `BrainOperationLog` | `operation`、`phase`、`counts`、`duration`、`error` | 展示和审计每次同步/Dream/检索流程 |

Scope 指纹建议由以下内容计算：

```text
SHA256(
  排序后的 sourceKey + sourceVersion
  + permissionEpoch
  + schemaVersion
  + embeddingModelVersion
  + rerankModelVersion
  + synthesisPromptVersion
)
```

具有相同指纹的用户复用同一 Scope，避免每人完整复制一套 GBrain；一旦权限范围不同，必须使用不同 Scope。

### 4.2 权限模型

权限计算分为四层，不能只依赖前端菜单或 GBrain source 成员关系：

1. **功能能力**：决定菜单是否显示，例如组织管理、行业库管理、知识上传、知识删除、图谱查看。
2. **资源范围**：决定能操作哪一个组织、知识库、文档或派生结果。
3. **GBrain source 隔离**：只把允许的知识写入对应 source 或 Scope。
4. **数据库最终校验**：检索候选、引用、预览、下载、生成上下文前再次校验。

权限变化时遵循“先收紧、后异步重建”：

```text
权限撤销
  → 立即更新数据库 ACL 和 permissionEpoch
  → 立即使旧 Scope、检索缓存、引用缓存失效
  → 异步移除 source 成员或归档旧 Scope
  → 生成新的 Scope
```

即使异步任务延迟，也不能使用旧权限结果。

### 4.3 组织、行业库和个人库规则

| 资源 | 阅读规则 | 内容维护 | 管理规则 |
|---|---|---|---|
| 个人库 | 仅本人 | 本人增删改、添加文本、预览 | 不可共享；需要共享应创建行业库 |
| 组织库 | 下级组织可读上级组织库；上级不可读下级库 | 本级组织管理员及其上级组织管理员 | 本级组织管理员可管理本级及所有下级，不可修改上级或旁支 |
| 行业库 | 按人、组织、角色授权，授权最终展开到人 | 当前行业库管理员 | 创建者可删除和设置管理员；管理员可维护知识和授权；无管理关系不可显示管理入口 |

组织管理员的委派必须满足：本级组织管理员可以设置本级及所有下级组织管理员；不能设置上级组织管理员，也不能修改上级组织的组织属性。

## 5. 文档入库升级流程

```text
上传原文件
  → 文件名/格式/大小/病毒校验
  → 原文件持久化，生成文档版本
  → 异步解析为规范 Markdown
  → 结构化切分：标题、段落、表格、条款、页码、位置
  → 生成内容 hash、Chunk、关键词索引、Embedding
  → 写入对应原始 Source 并增量 sync
  → 抽取事实/实体/关系/标签
  → 计算受影响 Scope
  → 在 Scope 内增量 Think/Synthesize/Graph
  → 原子发布派生结果
  → 记录 Compile Truth 和操作日志
```

必须保留三类产物：

- **原始产物**：原文件、文件名、格式、版本和上传者姓名。
- **检索产物**：规范 Markdown、Chunk、关键词索引、Embedding、Rerank 信息。
- **智能产物**：事实、实体、关系、总结、概念页、缺口报告和引用清单。

智能产物必须带 `derivedFrom`、原文版本、生成时间、模型版本和 Scope 指纹；无来源的总结不得进入政府场景的最终证据上下文。

文档更新只处理内容 hash 变化的页面和 Chunk；删除只删除受影响 source 映射和派生结果，不完整重建所有用户的 source。

GBrain 的基础设施文档描述了 Markdown/Git → Chunk → Embedding → 数据库 → 混合检索的链路，并采用关键词与向量结果融合；本项目在此之上增加权限 Scope 和派生智能层。  
参考：[Infra Layer](https://github.com/garrytan/gbrain/blob/master/docs/architecture/infra-layer.md)。

## 6. 跨 Source 检索流程

一次问答应按以下顺序执行：

1. 读取当前会话上下文，识别代词、追问和范围词；历史内容只用于消解语义，不直接视为事实证据。
2. 根据当前用户、组织、角色、人员授权和有效期计算 `Scope`。
3. 在 Scope 内进行关键词检索、向量检索、混合融合、查询扩展和重排。
4. 同时检索 Scope 的事实页、概念页和关系图谱，但派生页只作为导航和召回增强。
5. 将候选结果回溯到原始文档和原始 Chunk。
6. 对知识库、文档、Scope、引用和预览链接执行数据库最终权限校验。
7. 使用 DeepSeek 基于通过校验的原文证据生成回答。
8. 输出完整引用：知识库、文档中文名、页码/章节/Chunk、原文片段和在线预览链接。
9. 对“全部、完整、多少条、全文”等问题扩大候选、关闭过早截断，执行完整性检查；不能用针对某个问题关键词的特例规则代替通用机制。

检索策略应采用分层回退：精确关键词 → 混合检索 → 图谱/关系召回 → 派生总结辅助 → 原文重建。任一阶段都不能绕过最终 ACL。

GBrain 的 Brain-first Lookup 也建议优先使用知识库关键词和混合检索，再进行直接定位或外部回退；本项目应将外部回退限制为明确允许的公开信息场景。  
参考：[Brain-first Lookup](https://github.com/garrytan/gbrain/blob/master/docs/guides/brain-first-lookup.md)。

## 7. Dream、Think 和知识图谱

### 7.1 两级 Dream

#### Source Dream

负责单个原始 source 的确定性维护：lint、同步、索引、Embedding、孤立页面、反向链接、结构问题和基础事实抽取。

#### Scope Dream

负责当前权限范围内的综合智能：

- 跨 source 合并概念和实体；
- 生成带引用的主题总结；
- 识别事实冲突、知识缺口和过期内容；
- 形成组织/行业/个人范围内的知识图谱；
- 建立文档、条款、人员、组织、项目、风险和制度之间的关系；
- 对受影响的总结和关系执行增量重算。

不能把私密 source 直接交给无权限的全局 Dream。当前某些非 default source 的 Dream phase 被跳过属于隔离机制，不能简单视为失败；应由 Scope 编排器以明确的授权 source 集合调用跨 source 能力。

GBrain 的 Ambient Recall 文档将 `synthesize` 定位为跨页面推理，并提供 `context_pack`、`delta` 等上下文组织能力；这类操作应放在异步 Dream/Think 或明确的复杂问答路径，不应阻塞普通热检索。  
参考：[Ambient Recall](https://github.com/garrytan/gbrain/blob/master/docs/guides/ambient-recall.md)。

### 7.2 知识图谱

图谱至少支持以下节点和边：

```text
节点：组织、人员、角色、知识库、文档、章节、条款、主题、制度、项目、风险、时间
关系：属于、授权给、引用、定义、依赖、替代、冲突、适用于、负责、包含、来源于
```

图谱展示必须按当前用户 Scope 过滤；任何节点或边的来源文档被撤销后，图谱缓存和页面链接立即失效。图谱用于发现关系、扩大召回和解释答案，最终证据仍回到原文。

## 8. 变化驱动的增量更新

所有变化统一写入 Outbox，再由队列消费，避免数据库成功而 GBrain 未更新：

| 变化 | 影响范围 | 处理方式 |
|---|---|---|
| 新增/修改文档 | 所属 source、包含该 source 的 Scope | 增量解析、同步、Embedding、局部事实和总结重算 |
| 删除文档 | 原 source、相关 Scope、引用和图谱边 | 立即失效，异步清理和重算 |
| 知识库授权变化 | 受影响用户和 Scope | 先失效权限，再重建 Scope |
| 用户组织变化 | 该用户及同权限集合 | 更新有效读者集合和 Scope 成员 |
| 角色授权变化 | 受影响角色成员和 Scope | 增量重算授权范围 |
| 行业库管理员变化 | 管理能力和菜单 | 立即刷新能力缓存，不改变阅读授权，除非显式修改 |
| 模型/Embedding 版本变化 | 受影响 source/Scope | 分批重嵌入和重综合，旧版本可回滚 |
| Schema/提示词变化 | 对应派生页 | 只重建派生智能产物 |

队列要求：幂等 Job ID、去重合并、失败重试、死信队列、断点恢复、优先处理权限撤销、原子发布和可回滚版本。

## 9. 管理界面与可观测性

新增“GBrain 运行中心”，至少展示：

- Source、Scope、成员数和权限指纹；
- 最近一次同步时间、状态、增加/修改/删除页面数；
- Chunk、Embedding、事实、实体、关系、总结和缺口数量；
- Think/Synthesize/Dream 各阶段 `success/warn/skipped/failed`；
- 当前队列、重试次数、死信任务和错误原因；
- 当前 Compile Truth：输入版本、输出版本、来源链、模型版本、Scope 和发布时间；
- 检索命中率、空结果率、引用覆盖率、回答延迟和模型调用成本。

用户只能看到自己有权查看的 Scope 统计；系统管理员可以查看全局运维指标，但管理界面不得展示文档正文或越权引用内容。

## 10. 实施阶段

### 阶段 0：基线和开关

建立现有检索评测集、权限测试集和指标基线；所有新能力通过 feature flag 开启，保留回滚路径。

### 阶段 1：事件和版本治理

实现 Outbox、`permissionEpoch`、`knowledgeEpoch`、文档版本、幂等任务、操作日志和 Compile Truth。

### 阶段 2：Scope Brain

实现 `BrainScope`、Scope 指纹、同权限集合复用、Scope 成员同步和权限撤销即时失效。

### 阶段 3：跨 Source Think

增加 GBrain Gateway/编排器，优先使用带用户身份和 federated-read 边界的调用方式；在原生能力未完全接通前，保留应用层 `queryMany` 作为可观测的兼容路径，不允许绕过 ACL。

### 阶段 4：事实、实体、图谱和派生页

按政府业务优先落地制度、法规、合同、组织、人员、项目和风险等 Schema；所有派生页带来源和版本。

### 阶段 5：全量 Scoped Dream

上线 Source Dream、Scope Dream、变更触发 Dream、定时对账和失败恢复；普通问答走热检索，复杂跨文档问答才触发 Think/Synthesize。

### 阶段 6：评测、灰度和切换

以用户组和知识库为单位灰度，比较新旧答案、引用和权限结果；达到验收指标后切换为默认路径。

## 11. 验收标准

### 安全

- 权限撤销后立即不能检索、预览、下载或引用原内容。
- 原始 source、Scope 派生页、缓存、日志和引用链接均无越权泄露。
- 组织管理员不能修改上级或旁支组织。
- 行业库创建者、行业库管理员、内容维护者职责边界符合业务规则。

### 完整能力

- 同一权限范围内可跨多个 source 回答综合问题。
- 可生成带原文引用的范围内总结、事实、关系和缺口报告。
- 知识图谱按用户权限显示，并能从关系回到原文。
- 新增、修改、删除知识后只更新受影响的 source 和 Scope。
- 组织、角色、人员授权变化后 Scope 自动更新，动态增加人员仍能获得正确权限。
- 会话追问能结合历史语义，但历史消息不会替代知识库证据。

### 质量和运维

- 文档完整性问题不依赖“第 N 条”等问题特例，而通过结构化切分、宽检索和完整性校验解决。
- 关键问题的 Recall@K、引用准确率、答案完整性、空结果率均有基线和趋势。
- 每次 Dream/Think 都能看到具体输入、输出、阶段状态和失败原因。
- 失败任务可重试、可恢复、可回滚；服务重启后不丢任务。

## 12. 风险与取舍

| 风险 | 控制措施 |
|---|---|
| Scope 数量随权限组合增长 | 按 source 集合指纹复用；设置冷 Scope 回收和上限 |
| 派生总结过期 | 绑定输入版本，过期即降级为原文检索，不使用旧总结作为最终证据 |
| 权限撤销期间存在异步延迟 | 数据库 ACL 和缓存失效同步执行，队列只负责物理清理和重建 |
| 跨 source 成本和延迟上升 | 两阶段检索、候选裁剪、结果缓存、复杂问题才执行 Think |
| 图谱错误传播 | 图谱只做召回和解释，最终答案必须引用原文并可回溯 |
| 模型或 Schema 升级影响全量数据 | 版本化、分批重算、双版本并行和可回滚 |

## 13. 最终推荐

最终采用：

> **原始 Source 独立 + 权限范围 Scope Brain 跨 Source 综合 + GBrain Think/Graph/Dream + 平台数据库最终 ACL。**

这能同时满足：

- 不复制每个人完整知识库，降低存储和同步成本；
- 不因组织、角色或人员动态变化而失去权限准确性；
- 在权限范围内实现跨 source 的全局检索、总结、图谱和推理；
- 知识变化和权限变化只触发受影响范围的增量更新；
- 保留政府场景要求的可追溯、可审计、可撤销和可回滚能力。

本文件是待升级方案，不代表本轮已经完成全部改造。实施时建议先完成阶段 0～2，再以灰度方式启用跨 Source Think 和 Scoped Dream。
